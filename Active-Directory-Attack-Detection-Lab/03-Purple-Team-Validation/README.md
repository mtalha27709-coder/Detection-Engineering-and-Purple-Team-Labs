# Blue Team Detection & Investigation

# Overview

This document explains how Blue Team activities were performed during the Active Directory Attack & Detection Lab. After executing multiple Active Directory attack techniques from Kali Linux, Windows Server 2022 was monitored using Sysmon and Wazuh SIEM to detect suspicious authentication events, credential access, and Active Directory abuse.

The objective was not only to perform attacks but also to investigate them from a Security Operations Center (SOC) perspective by analyzing Windows Security Logs, Sysmon events, MITRE ATT&CK mappings, and Wazuh alerts.

# BloodHound Investigation

## Objective

Identify Active Directory enumeration activity performed by an attacker.

### Indicators

- LDAP Enumeration
- Active Directory Queries
- Enumeration of Users
- Enumeration of Groups
- Enumeration of Computers
- Domain Information Collection

### Investigation

The analyst verified that multiple Active Directory objects were queried within a short period of time. Such behavior is uncommon for normal users and can indicate reconnaissance before privilege escalation.

### MITRE ATT&CK

| Technique | ID |
|-----------|----|
| Account Discovery | T1087 |
| Permission Groups Discovery | T1069 |
| Domain Trust Discovery | T1482 |

# Kerberoasting Investigation

## Objective

Detect Kerberos ticket abuse targeting Service Accounts.

### Indicators

- Event ID 4769
- Multiple TGS Requests
- Service Account Enumeration
- Kerberos Authentication Activity

### Investigation

The Blue Team reviewed Kerberos Service Ticket Requests generated by the Domain Controller.

During the attack, a service ticket was requested for an SPN account. Windows generated Security Event ID 4769, while Wazuh successfully collected authentication events.

Although Wazuh mapped the activity to MITRE T1078 using its default ruleset, the actual attack performed was Kerberoasting (T1558.003).

### Windows Event

```
4769
Kerberos Service Ticket Requested
```

### MITRE ATT&CK

| Technique | ID |
|-----------|----|
| Kerberoasting | T1558.003 |

# Pass-the-Hash Investigation

## Objective

Detect NTLM authentication using password hashes instead of plaintext passwords.

### Indicators

- Administrative Login
- Remote Authentication
- NTLM Authentication
- PsExec Activity
- Privileged Session

### Investigation

The analyst observed successful administrative authentication originating from the attacker's machine.

Remote execution tools created administrative sessions that could indicate lateral movement inside the Active Directory environment.

### MITRE ATT&CK

| Technique | ID |
|-----------|----|
| Pass the Hash | T1550.002 |

---

# DCSync Investigation

## Objective

Detect unauthorized Active Directory replication.

### Indicators

- Replication Requests
- Credential Dumping
- DRSUAPI Activity
- Administrator Hash Extraction
- KRBTGT Hash Extraction

### Investigation

The attacker successfully executed a DCSync attack using Impacket.

The Domain Controller responded with credential replication data, including password hashes for Administrator, KRBTGT, service accounts, machine accounts, and domain users.

This activity represents one of the most severe attacks against Active Directory because it allows attackers to retrieve credential material without directly accessing the NTDS database.

### MITRE ATT&CK

| Technique | ID |
|-----------|----|
| DCSync | T1003.006 |

# Wazuh Investigation Process

For every alert, the following information was reviewed:

- Alert Severity
- Rule ID
- Timestamp
- Source IP Address
- Destination Host
- Username
- Windows Event ID
- MITRE ATT&CK Technique
- Process Information
- Authentication Method

This investigation process helps analysts determine whether the activity is legitimate administrative behavior or a potential security incident.

# Blue Team Recommendations

- Enable Advanced Windows Auditing.
- Deploy Sysmon on all Domain Controllers.
- Monitor Event ID 4769 for Kerberos abuse.
- Restrict Domain Admin privileges.
- Use Group Managed Service Accounts (gMSA).
- Rotate service account passwords regularly.
- Monitor NTLM authentication.
- Detect abnormal Active Directory replication requests.
- Enable centralized log collection using Wazuh SIEM.
- Continuously map alerts to MITRE ATT&CK techniques.

# Conclusion

This lab demonstrated how multiple Active Directory attacks can be detected and investigated from a Blue Team perspective using Windows Security Logs, Sysmon, and Wazuh SIEM.

By combining attack simulation with defensive monitoring, security analysts gain practical experience in identifying reconnaissance, credential access, lateral movement, and Active Directory replication abuse. This approach reflects real-world Security Operations Center (SOC) workflows and strengthens both detection engineering and incident response capabilities.
